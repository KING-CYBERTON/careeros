## P1-T02 call sites that can outlive a `withOrgContext` scope

AsyncLocalStorage keeps a scope's store on timers, un-awaited promises and generators created inside it. Once the scope ends, `db` and `getPool()` throw `scope_closed` for those continuations (they never fall back to the global pool or to the released client), and a nested `withOrgContext` from one throws the same. These sites are not refactored in T02; streaming and agent runs get their own scope handling in T07 and T08.

| Call site                                                        | Behaviour now                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `custom-domain/service.ts:241` `void recheckStaleDomains()`      | Runs after the scope when started from a scoped caller; its queries fail loudly with `scope_closed`, and the existing `.catch` logs a warning. Acceptable until its table batch; the Traefik provider endpoint is moved to a `security definer` lookup in D10. |
| `resume/public-pdf.ts:111` shared render promise                 | If started inside a scope, any `db` call it makes after the scope ends fails loudly for every request awaiting it. Acceptable until its table batch (public render, no org-scoped reads today).                                                                |
| `agent/service.ts`, `agent/cancellation.ts` timers and long runs | Timers and runs that query after the scope ended fail loudly with `scope_closed`. Moved to explicit per-run scopes in T07/T08.                                                                                                                                 |
| `resume/event-router.ts:34` `async function*` handler            | The iterator is consumed by oRPC outside the scope, so it runs on the global pool with no org (not the released client); `listenOnPostgres` also gets a clear `connect_in_scope` if ever run inside a scope. Streaming scope handling in T07.                  |
| `cover-letters/draft.ts` `async function*`                       | Same as above: resumed outside the scope it has no org context; resumed from a continuation of the scope after it ended it throws `scope_closed`. Acceptable until its table batch.                                                                            |
