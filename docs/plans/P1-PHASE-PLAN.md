# Phase 1 — Multi-tenancy: Phase Plan

**Status:** Approved (Opus, 2026-10-31), except D6 which waits on Stephen · specs: [P1-T01](P1-T01-org-plugin.md), [P1-T02](P1-T02-tenancy-core.md), [P1-C01](P1-C01-db-role-split.md); the rest follow per sub-phase · **Exit tag:** `0.1.0` · **Estimate:** 2 to 3 weeks

## Goal

Every user-owned row belongs to exactly one organization, PostgreSQL enforces that with RLS under a non-superuser app role, the server resolves the active organization on every request and background job, and organizations have owners, admins, members and invitations. The isolation suite from P0-Q02 covers every tenant table and passes in CI.

## Exit criteria (PRODUCT.md §13)

1. Every tenant table: `organization_id text not null`, RLS **enabled and forced**, `tenant_isolation` policy, composite index led by `organization_id`, registered in the isolation registry. The coverage check fails CI if any `public` table is neither registered nor on the global allow-list.
2. DB check (P0-Q02) passes for every registered table as `careeros_app`; API check passes for every tenant-scoped route group; ID-fuzz test (Org A ids in Org B requests → 404) passes.
3. The app runs with `DATABASE_URL` = `careeros_app` (NOSUPERUSER, NOBYPASSRLS) and migrations with `DATABASE_MIGRATION_URL` = table owner, in CI and on staging.
4. Opus sign-off: no open Critical or High findings.

## Risks

| Risk                                                                                                | Mitigation                                                                                                                     |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Upstream code that bypasses the `db` proxy (direct `getPool()` / raw `pg`) runs without org context | T02 greps for every `getPool`, `new Pool`, `pool.query`; each one is wrapped or justified in the spec; RLS fails closed anyway |
| Mobile app breaks on API changes (F11)                                                              | Mobile stays out of CI; API contracts keep backward-compatible shapes where possible                                           |
| Upstream monthly merges touch the same files                                                        | Edits stay in `@careeros/tenancy` and thin `CAREEROS:` hooks; every touched file in UPSTREAM_PATCHES                           |
| Connection pool exhaustion from per-request client checkout                                         | Same pool size as today (one client per request already happens per query); P1-Q01 load test measures it                       |
