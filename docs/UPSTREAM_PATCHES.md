## P1-T02 call sites that can outlive a `withOrgContext` scope

AsyncLocalStorage keeps a scope's store on timers, un-awaited promises and generators created inside it. Once the scope ends, `db` and `getPool()` throw `scope_closed` for those continuations (they never fall back to the global pool or to the released client), and a nested `withOrgContext` from one throws the same. These sites are not refactored in T02; streaming and agent runs get their own scope handling in T07 and T08.

| Call site                                                                                                                                                                   | Behaviour now                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `custom-domain/service.ts:241` `void recheckStaleDomains()`                                                                                                                 | Runs after the scope when started from a scoped caller; its queries fail loudly with `scope_closed`, and the existing `.catch` logs a warning. Acceptable until its table batch; the Traefik provider endpoint is moved to a `security definer` lookup in D10.                                                            |
| `resume/public-pdf.ts:111` shared render promise                                                                                                                            | **Fixed in P1-T04.** The render's database write (revalidating the resume under the owner lock) goes through a runner from `captureOrgScope()` taken inside the request's scope, so it opens its own scope for the resume's organization when other visitors still await the render.                                      |
| `agent/service.ts` step-draft persistence (`onStepEnd`), final persistence and run cleanup (`onFinish`), and every tool `execute` (document, web, attachment, career tools) | **Fixed in P1-T03.** `send` calls `captureOrgScope()` at the start of the request; each of these writes runs through the captured runner in a fresh scope of the same organization, with its own briefly held client. `agent/cancellation.ts` timers only use Redis or coordination, never `db`, so they need no wrapper. |
